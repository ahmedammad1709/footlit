● Each store counts only its own installs. There is no combined number unless

  Counting

  - Chrome Web Store: its dashboard shows Chrome users and installs.
  - Firefox (AMO): its Developer Hub shows daily users and downloads for Firefox
    only, with a CSV export.
  - Edge: if you submit there later, that is a third separate dashboard (Partner
    Center).

  For a total, add up users (not downloads) from each dashboard. Chrome's
  "users" and AMO's "daily users" count the same kind of thing, active installs,
  so they can be added. Downloads and installs include people who later
  uninstall, so don't mix them with users.

  Putting Footlit on Firefox (AMO)

  Your ready-to-upload files are in release/: footlit-firefox-1.0.0.zip and
  footlit-source-1.0.0.zip. They match the version you submitted to Chrome.

  1. Go to addons.mozilla.org/developers and sign in with a Firefox account.
     Turn on 2-factor authentication, which Mozilla requires for developers.
  2. Choose Submit a New Add-on, then On this site (the public listing).
  3. Upload footlit-firefox-1.0.0.zip. The automatic check should pass.
  4. Leave Android unticked, because I've only tested the desktop version.
  5. When it asks whether you use minified or bundled code, say Yes and upload
     footlit-source-1.0.0.zip. In the notes for the reviewer, put:
  ▎ Node 22. Run npm install then npm run build:firefox to produce 
  dist-firefox/. Bundled with esbuild (TypeScript). No network requests, no 
  remote code. To test: open github.com, click the Footlit toolbar icon, press 
  Rehearse on any event to play an animation. Permissions: storage and 
  github.com only.
  6. Fill in the listing from docs/STORE_LISTING.md. Use the Developer Tools or
     Web Development category. Add your site's privacy page as the privacy
     policy, and upload the screenshots from store/ (the screenshot-*.png
     files). You need to pick a license for the listing yourself.
  7. Submit. Review usually takes hours to a few days.
  8. When it's approved, send me the listing URL and I'll add a Firefox install
     button to the site.

  Don't change the extension ID in the manifest. If it changes, AMO treats the
  upload as a different add-on.

  A "total downloads" number

  - Don't add counting inside the extension. Your privacy page, the Chrome
    disclosure and the Firefox manifest all say nothing leaves the browser. A
    tracking ping would break all three, and it still couldn't combine the
    stores without running a server.
  - Safest: a monthly spreadsheet of the dashboard numbers.
  - On the website: I can build a small config-driven "Used by N people"

    a public number to fetch). The Firefox number can be pulled automatically at
    build time from AMO's public API. I'd leave it off until the number is
    large enough to help, since a small number can hurt more than help.
  - Install-click counting: a cookie-free analytics tool such as Vercel
    Analytics or Plausible can count clicks on the "Add to Chrome" and "Add to
    Firefox" buttons and show which posts brought visitors. That counts clicks,
    not real installs, but it is useful for marketing and doesn't touch the
